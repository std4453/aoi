# AoI 界面与交互规范

此文档约束新功能和修改中的界面；现有页面逐步对齐。实现优先复用 `Button`、`IconButton`、`ActionRow`、`TaskSummaryContent`、`Modal`、`ImportSources`、`FormField`、`TextInput`、`PasswordInput`。上传过程中的标签、密码、重复确认和错误使用卡片内交互。

## 视觉基础

- 页面采用深色背景；区块使用 gray-900、gray-800 边框、rounded-xl、16px 内边距，弹窗 rounded-2xl、20px 内边距。相邻设置区块保持统一间距与标题层级。
- 全局 `1rem = 16px`，字体、间距与图标按此基准缩放。默认面向移动端，后续 UI 验证和截图使用 iPhone 16 Pro 的 402 × 874 CSS px 视口；长页面优先分屏截图，不能用桌面宽度代替移动端验收。
- 正文 white / gray-200，辅助说明 gray-400，次要元信息 gray-500。说明只保留操作必要的信息，避免重复标题或用法。
- 主操作使用 blue-600，悬停 blue-500；成功 green，待确认 yellow，错误 red。状态必须同时有文字或可访问名称，不能只依赖颜色。
- 信息中的图标用于身份或状态，不叠加图标底板。设置中的外部来源可使用品牌 `IconButton` 和按钮外的名称，配置角标可访问名称为「已配置」；这表示存在配置，不表示登录验证成功。上传区「导入自」后使用 32px 品牌图标的 `IconButton`，保留来源名称的可访问标签。
- 折叠任务和任务 toast 复用 `TaskSummaryContent`：左侧是来源类型图标（文件、文件夹、MEGA、Pixiv）和 `text-xs` 常规字重标题，随后是状态图标与状态文本，或进度。任务卡片的标题／状态两列固定 2:1；toast 按内容所需宽度紧凑排列，不按比例分列，也不拉满固定宽度。空间不足时标题省略，状态区也限制最大宽度以避免长提示挤出操作。最右侧是独立的收起／展开、前往或确认 `IconButton`，不能被正文挤压。
- 折叠卡片的已知进度只显示 6px 高的进度条，不显示状态图标、阶段文字或百分比；展开后标题的状态区只显示当前步骤文字和状态图标，正文显示完整进度条、传输量和百分比。摘要进度条保留可访问的阶段与进度值。未知进度只显示阶段或活动指示。剩余时间仅在有足够的实际传输采样时显示，不能从任务创建时间推算或编造。长标题、失败原因、无进度与 100% 都要验证。

## 按钮与表单

- 普通操作一般使用纯文字 `Button`；图标操作使用带可访问名称的 `IconButton`。`Button` 支持可选前置图标，但默认不使用「图标 + 文字」；明确例外是虚线边框的「继续上传」，以及初始上传区的「选择压缩包」「选择文件夹」，允许图标辅助识别上传入口与来源。其他例外应先补充本规范，不能随意给 action 添加装饰图标。来源／状态信息、标签选择器等复合信息控件不混入 action 区。
- 用整个步骤判断操作优先级，而不是对每个子区块分别加主按钮。同一操作组只有一个 primary action，放最右侧；取消、返回、查看详情等 secondary action 在左。使用 `ActionRow` 等分可用宽度；仅有一个可用操作时可独占一行，不为凑布局发明操作。不能同时出现语义重复的「保存」和「完成」。
- 文件／文件夹选择后的表单，以及 MEGA／Pixiv 地址表单，底部统一为「取消上传」和「开始上传／开始导入」。完成卡片为「查看图包」和「完成」；待密码、重试、暂停等步骤也遵守左次右主。按钮放在整个步骤的正文之后，而不是嵌入提示色块。
- 保存成功关闭配置弹窗；右上角关闭退出。保存请求期间禁用重复提交；失败保留输入并在原处显示错误。空输入、尚未加载、未修改时禁用保存。
- 破坏性删除使用红色语义并在必要时确认，不挤占日常流程的主操作。确认弹窗中取消在左，确认在右。
- 表单使用持久可见 label，placeholder 只提供例子。输入框 gray-800 背景、gray-700 边框、rounded-lg，键盘焦点清晰可见。禁用状态降低透明度并使用不可用光标。
- Pixiv refresh-token 在配置弹窗以普通文本回显，可编辑；只有打开配置时显式获取，状态角标不获取 token。关闭不保存，清除登录态立即保存空配置并反馈结果。
- 标签以紧凑 chip 展示，选择交互复用普通上传的 TagSelector，不以逗号文本代替标签。自动识别只填默认值，不覆盖用户修改。

## 弹窗与设置

- 短配置使用弹窗；多步骤或复杂配置使用独立页面。弹窗有清晰标题、右上角关闭与底部右对齐操作区，不在弹窗里重复嵌套设置卡片。
- 设置的「外部来源」与其他设置 section 使用相同卡片样式，内部通过可扩展的来源描述列表展示图标。上传页的初始选择区域采用透明、虚线边框：上传图标与简短的「上传图包」文字、居中并列且带类型图标的选择压缩包／文件夹按钮、下方居中的「导入自」和品牌图标入口。两个选择按钮下方显示支持 ZIP、RAR、7Z 与文件夹的提示，「导入自」上方保留更大的分组间距。选择来源、压缩包或文件夹后，填写表单的区域改为实色背景与实线边框的普通卡片。整个区域仍支持拖放；默认不出现拖入说明，只有文件拖入 hover 时临时隐藏原内容，显示上传图标和松开提示，区域高度保持不变，移出恢复原表单和草稿。普通文字或链接拖动不能触发文件拖放态。
- 弹窗提供 dialog 名称；按钮可键盘操作，图标按钮有 aria-label；异步反馈使用 status / alert。小屏保持安全边距，不溢出横向宽度。

## 核心链路：上传和外部导入

1. 选择文件/目录，或选择来源输入网址。Pixiv 服务端识别名称和作者标签；作者以外的作品标签不自动导入。识别不阻断导入，提前提交时后台补齐默认值。已创建标签不随取消删除。
2. 上传、下载、解包、校验、生成预览统一使用任务卡片。已知总量时展示真实进度；未知总量仅显示阶段与活动指示，不能伪造百分比。
3. 表单与任务共用标题行规范：折叠时来源图标16px、标题12px，上下内边距6px；展开时来源图标20px、标题14px，上下内边距10px，字号、图标尺寸及内边距通过240ms过渡。状态文字、状态图标和折叠按钮保持尺寸不变。每张展开卡片按「标题／摘要 → 提示 → 正文 → 底部操作」组织，提示的背景颜色仅覆盖提示本身。重复检测中的黄色块到「此图包可能已被上传过，请确认是否继续」结束；匹配图包是普通背景正文，最底部为左侧「取消任务」、右侧「继续上传」。不得用黄色大容器包住整个步骤，也不得在匹配图包中再放主操作。等待确认时保留任务；已能确定的错误立即在上传页展示。
4. 失败卡片使用红色边框，状态不加「待处理」；能够判断时显示上传、下载、解压、校验或预览生成失败，否则显示处理失败。错误正文给出简短的用户说明，不直接显示路径、堆栈或命令输出；历史任务也遵循该规则。错误提供问题、原因、解决方式及适用操作：缺登录态指向来源配置；可恢复失败提供重试；坏压缩包或密码错误提示重新上传。失败图包允许删除，取消需要说明将删除当前任务并确认。
5. 缩略图生成后允许查看预览。完成状态中「查看图包」为 secondary，「完成」为右侧 primary；确认后任务移除，图包保留。ugoira 展示动画标识，查看器提供播放/暂停。
6. 所有来源共用服务端持久化任务列表，刷新后恢复，完成须确认才移除。一次只展开一个任务；填写中的表单支持主动折叠，展开其他任务时也自动折叠，保留来源标题（如「MEGA 分享」）和图标的实色小卡片；点击标题恢复表单并折叠当前任务。尚未选择来源的上传区域折叠成虚线「上传图标 + 继续上传」入口。切换不丢失输入，内容保持挂载，任务创建后待折叠动画结束再清空表单，避免替换内容造成闪烁；遵循系统减少动态效果设置。任务列表上方显示左对齐灰色小字「任务列表」。其他 tab 收到待处理或完成状态时显示可跳转的底部 toast，刷新重新提示未处理任务；全屏查看时避开缩略图栏。

## 核心链路：浏览、查看与生成

- 图包列表以封面、名称、标签和处理状态帮助识别；处理失败必须可见，打开详情后保留重试/删除出口。
- 静图与动图共用图片池、预加载、模糊占位、尺寸适配及缩放/拖动/滑动手势。图片承载容器必须有明确的视口宽高，保证 max-height 的百分比约束生效；默认完整适屏，放大后允许在缩放边界内拖动。动图进入查看器时自动播放，可手动暂停；动画只更新共享图片元素的帧，播放控件位于查看器浮层，不随图片缩放；切换时停止动画并恢复缓存封面。播放、暂停、切换与关闭使用明确图标和可访问名称，避免说明文本遮挡内容。
- 生成/下载沿用真实阶段反馈，提交时防止重复触发，成功后提供明确下载入口，错误保留可恢复的编辑状态。

## 验收

至少核对初始、读取中、未修改、已修改、提交中、成功和失败状态；检查按钮顺序、小屏布局、键盘焦点与配置回显。上传改动另测取消、删除后切换 tab、重复检测和缩略图完成状态。PR 附相关界面截图，截图使用测试配置，避免暴露个人凭据。
