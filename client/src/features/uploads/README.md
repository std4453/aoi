# 上传任务边界

上传业务集中在此目录；通用表单、标签选择弹窗和图包 API 仍由各自模块提供。

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `task-store.ts` | 任务同步、统一操作、并发版本、串行持久化、缓存失效 | 表单、TUS 细节、卡片动画 |
| `local-upload.ts` | TUS、文件夹并发、重选校验、暂停恢复、取消与服务端交接 | React 生命周期、草稿和页面状态 |
| `UploadForm.tsx` / `UploadDraftForm.tsx` | 来源选择、拖放和完整草稿表单，包含标签、登录配置与提交操作 | 任务卡片和上传执行 |
| `draft.ts` | 远程来源适配表、元数据防抖、手动编辑保护、提交参数 | 任务列表与上传执行 |
| `view-state.ts` | 展开、一次性图包定位、退出快照、内存滚动点 | 服务端任务状态和删除请求 |
| `task-display.ts` | 跨来源的文案、语义状态、进度和错误解释 | CSS 与页面交互 |
| `TaskPresentation.tsx` | 卡片和通知共用的颜色、标题、提示及 action 样式 | 任务操作 |
| `TaskToast.tsx` | 上传通知的摘要、状态颜色和底部位置，组合通用 Toast | 通知容器、计时和退出动画 |
| `useUploadTasks.tsx` | 独立订阅入口、应用级轮询、服务与视图的接线 | 上传执行实现 |

任务仓库、本地执行器、草稿和视图均为应用会话内的单例。页面或 Hook 卸载只移除订阅，不中止上传；页面外的导航角标和任务通知不订阅草稿。刷新浏览器后只恢复服务端任务，本地文件必须重新选择。

执行器通过报告接口更新仓库；仓库删除成功后发出事件，视图独立保留 240ms 快照完成退出动画。详情页通过内存请求展开对应任务，上传页在任务加载后消费请求，URL 不承担动作信号或筛选。

`server/test/upload-client-lifecycle.test.ts` 用真实仓库、执行器与草稿搭配内存 API/TUS 替身，覆盖跨订阅持续上传、刷新重选、文件夹并发、暂停恢复、串行写入、过期元数据、取消交接竞态及一次性定位；随 `npm run check` 在 CI 执行。

任务通过 `isRemote` 区分传输类型，通过 `errorCode` / `errorCategory` 提供错误语义。前端不匹配诊断文案；服务端在来源、解压或网络边界生成错误码，后台作业及任务重启后保留。旧解压作业通过服务端适配保留密码恢复能力；其他没有错误码的旧任务按处理阶段显示通用提示。
